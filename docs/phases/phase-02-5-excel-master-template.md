# Phase 2.5 — Product Master Excel Template (physical contract)

Status: **Batch 3 — Approved and recorded (2026-09-12, owner; decision
D-033)**

---

## Purpose

Turn the D-028 semantic Excel import contract into a concrete,
physical workbook specification: exact workbook name, sheet names,
column names, column order, data types, required/optional status,
canonical value mappings, validation behavior, import mapping, and
provenance behavior.

This closes the D-028 physical-mapping dependency (previously open
pending the owner workbook): the physical contract is now defined by
this document and **D-033**, and is **OWNER-APPROVED configuration** —
recorded by the AI from the owner's approval, not invented or
AI-defaulted.

This remains **specification only**: no importer, backend code,
database tables, APIs, WooCommerce/n8n integration, or Phase 3 work is
started, and no actual `.xlsx` file is created yet (the template file
itself is produced at the implementation task from this contract).

## Design principles (unchanged from D-028)

- The workbook is a **human input interface** — input-only, temporary,
  never a Source of Truth, never transactional/inventory/order storage,
  never the authority for identifier generation (D-006, RULES §13).
  WooCommerce remains the future transactional Source of Truth.
- The seller enters **human-readable values** and never needs to know
  Variant ID, internal database IDs, SKU construction rules, UUID
  generation, provenance internals, or event-idempotency internals.
- AI must never generate or assign Product ID, Variant ID, SKU, price,
  stock, payment/shipping/order facts (D-014 rule 12, D-017 rule 7,
  D-021, authority matrix `DATA_MODEL.md` §13.7).

## Workbook

- **File name:** `product-master.xlsx` (ASCII file name for

- **Sheets (exactly 4, in this order):**

| 3 | `راهنما` | Persian seller instructions (never imported) |

- **No additional sheets.** No extra business-data sheet is needed; the

## Identifier handling (authority classes)

| Field | Class | Rule |
| --- | --- | --- |
| `شناسه محصول` (Product ID) | **human input** | Seller supplies it; format `P` + 5 digits (`P00001`); immutable (D-014/D-017); duplicates rejected |
| `شناسه تنوع` (Variant ID) | **generated by tooling** | Leave blank → approved deterministic tooling generates a canonical UUIDv4 at import (after human dry-run promotion). If filled (round-trip), must be canonical lowercase hyphenated UUIDv4 and unique. The seller never needs to enter it (D-015/D-017) |
| `کد کالا (SKU)` | **read-only / tooling-validated** | Seller should leave blank; approved deterministic tooling derives it from Product ID + approved axis codes (D-014/D-032) after human confirmation. If filled (round-trip), it is validated (format, codes, uniqueness) — never auto-corrected |
| prices, stock, statuses | **human input / validated** | Validated; never auto-corrected; AI never creates or changes them |

The workbook never becomes the authority for generating any
identifier; identifiers remain governed by D-014/D-015/D-017.

**Category note (necessary second column):** Batch 1 records that
identical leaf names exist under both primaries (تیشرت، پیراهن، شلوار،
هودی و سویشرت، ژاکت و بافت، کت و جلیقه) and that **a category term
belongs to exactly one primary**. A single category column therefore
cannot disambiguate `تیشرت` (women's vs men's are separate terms). The
physical contract thus uses `دسته‌بندی اصلی` (primary) + `زیردسته`
(leaf, primary-scoped) — this is the faithful physical encoding of the
approved Batch 1 structure, not a new category concept. No new
category value is created.

**Color/Size are NOT product-level columns.** They are variant-defining
axes (D-018) and live on `تنوع‌ها` only. No non-authoritative
product-level display duplicate is created.

## Sheet 2 — `تنوع‌ها` (Variants)

One row = one Product Variant. Required minimums follow D-021
(Variant ID, Product ID, SKU, all active variant-defining attributes,
Variant status) — with Variant ID and SKU allowed blank at input and
issued by approved deterministic tooling (see identifier table).

| # | Column | Semantic field | Type | Requirement | Validation |
| --- | --- | --- | --- | --- | --- |
| 1 | `شناسه تنوع` | Variant ID | UUIDv4 | optional at input | blank → tooling generates (canonical lowercase hyphenated UUIDv4); if present: canonical format, unique, never reused |
| 2 | `شناسه محصول` | parent Product ID | text | **required** | must match an existing `محصولات` row in the same workbook |
| 3 | `کد کالا (SKU)` | SKU | text | optional at input (read-only/tooling) | if present: D-014 format, valid D-032 codes, unique; never auto-corrected |
| 4 | `رنگ` | Color term | controlled | required-if Color active | exact canonical value from the 25 approved colors |
| 5 | `خانواده سایز` | Size family | controlled | required-if Size active | exact: `حروفی` (alpha) / `عددی` (numeric) / `کمر` (pants waist) |
| 6 | `سایز` | Size term | controlled | required-if Size active | exact term; **must belong to the selected family** |
| 7 | `قیمت تنوع (تومان)` | variant price override | integer ≥ 1 | optional | numeric Toman; blank = inherit product price (D-024) |
| 8 | `قیمت فروش ویژه تنوع (تومان)` | variant-level sale price | integer ≥ 1 | optional | must be < applicable base (override, else product list price) |
| 9 | `تاریخ پایان فروش ویژه تنوع` | variant sale valid-until | date | optional | empty = no expiry; expired sale ignored (D-025) |
| 10 | `وضعیت تنوع` | variant status | controlled | **required** | same mapping as product status; mirrors product lifecycle (D-022 rule 7) |

**Active-axis encoding (deterministic, D-018):**

- Color is **active** for product P iff at least one `تنوع‌ها` row of P
  has `رنگ` filled; then **every** variant row of P must have `رنگ`
  filled (a partially filled axis = INVALID, never guessed).
- Size is **active** for P iff at least one row of P has
  `خانواده سایز`/`سایز` filled; then every row of P must have both
  filled, and `سایز` must belong to `خانواده سایز`.
- Zero variant rows for P = **simple product** (D-018 rule 3).
- Rows with `رنگ` only = color-only product (one active axis).
- Rows with `رنگ` + size = Color + Size (canonical order in the derived
  SKU: Color then Size, D-018 rule 6).
- Duplicate active-axis combination under one product = rejected
  (D-014 rule 11); no `-2` suffix is created by the seller — that
  emergency valve belongs to approved tooling only.

**No inventory/stock columns.** Inventory design remains an owner-gated
open item (D-016.I); no stock field — authoritative or display — is
created in this batch. Nothing is silently closed.

## Price mapping (D-024 / D-025 — unchanged)

- Numeric Toman only: positive integers, no thousand separators, no
  currency text, no decimals (D-010). Formatted strings are rejected.
- `قیمت پایه (تومان)` is **required if** any of: (a) the product is to
  be publishable (publication minimum: resolvable price, D-021);
  (b) any variant row of the product lacks `قیمت تنوع`;
  (c) `قیمت فروش ویژه (تومان)` is set (a sale needs a base).
- `قیمت تنوع (تومان)` is the **variant price override** — used only
  when the variant's base differs from the product list price (D-024).
- Effective price precedence (deterministic, D-024 rule 4 + D-025):

  valid variant sale → valid product sale → variant override →
  product list price

  (an invalid/expired variant sale falls back to the product-level
  sale, then the base — exactly as approved).
- `قیمت فروش ویژه …` must be **< its applicable base**; sale ≥ base is
  a validation error (never clamped). Zero/negative effective price is
  invalid. Exactly one effective sale; no stacking; expired sales are
  ignored. No coupons, campaigns, or percentages are stored.
- AI cannot create or change any production price (it may only
  recommend, per the authority matrix).

| Excel value | Canonical value | Applies to |
| --- | --- | --- |
| `پیش‌نویس` | `draft` | وضعیت محصول، وضعیت تنوع |
| `فعال` | `active` | وضعیت محصول، وضعیت تنوع |
| `بایگانی` | `archived` | وضعیت محصول، وضعیت تنوع |
| `منتشرنشده` | `unpublished` | وضعیت انتشار |
| `در بررسی` | `in_review` | وضعیت انتشار |
| `منتشرشده` | `published` | وضعیت انتشار |
| `برداشته‌شده` | `withdrawn` | وضعیت انتشار |

- No new status values exist; anything else is INVALID.
- Variant status mirrors the product lifecycle (D-022 rule 7).
- A `منتشرشده` value is honored only through the normal D-023 path:
  the deterministic import validates the full D-021 publication
  minimum, and the human promotion of the dry-run is the human-approved
  transition (approved tooling executes; AI never publishes).
- Publication status never substitutes for product status (D-023).

## Controlled vocabularies (Registry v1 — exact values only)

- **Category:** exactly the Batch 1 tree — primaries
  {پوشاک زنانه، پوشاک مردانه} and their 12 + 8 leaf terms, primary-
  scoped (see the category note above).
- **Color:** exactly the 25 Batch 1 canonical terms; codes exactly per
  D-032 (BK, WHT, GRY, CHR, GY1, CRM, BEG, BRN, NCF, NVY, BU, BU1,
  PTB, GRN, VGR, DGN, RED, BRG, PNK, PK1, PRP, RNG, YW, KHK, CAM).
- **Size:** exactly the three Batch 1 families with D-032 codes —
  Alpha (`حروفی`): XS→XS, S→S, M→M, L→LG, XL→XG, XXL→XXG, 3XL→3XG,
  4XL→4XG (display labels stay `L`, `XL`, … per D-020 rule 4);
  Numeric (`عددی`): 34→34 … 54→54; Pants Waist (`کمر`): 28→28 …
  44→44. Numeric 42 and Pants Waist 42 remain distinct terms in
  distinct families.
- Resolution is **exact matching after basic case/whitespace
  normalization** (D-019). No aliases, no equivalence mappings, no
  fuzzy matching, no automatic conversion, no automatic vocabulary
  creation. Unmapped provided values are retained and sent for human
  review — never silently added to any registry.

## UNKNOWN / NOT_PROVIDED / INVALID (D-028/D-021 semantics preserved)

- **Blank cell = `NOT_PROVIDED`** — information not supplied.
- **Exact cell value `نامشخص` = `UNKNOWN`** — explicitly unknown; the
  Persian-facing realization of the approved "explicit controlled
  value" rule (section 10 of the batch). Valid only in the optional
  structured fields (`نام انگلیسی` and columns 6–16, 19–21); in
  `توضیح کوتاه`/`توضیحات` text is taken as-is. `UNKNOWN` is surfaced
  for human review and is NOT automatically blocking (D-021).
- **INVALID** = supplied but structurally/business-rule invalid;
  detected by validation, rejected with a row-level error, never
  auto-corrected.
- The three states are never silently transformed into one another.

## Excel data validation (intended behavior — no formulas/macros in this batch)

- Dropdown (list) validation sourced from the `گزینه‌ها` named ranges
  for: `دسته‌بندی اصلی`, `زیردسته`, `رنگ`, `خانواده سایز`, `سایز`,
  `وضعیت محصول`, `وضعیت انتشار`, `وضعیت تنوع` — exact controlled
  values only; entries outside the list are rejected by Excel and, as a
  second layer, by import validation.
- **Dependent size-by-family dropdown:** desirable but not required for
  correctness. The deterministic alternative (and the normative
  behavior) is: family and size dropdowns are independent at Excel
  level, and **family membership is enforced deterministically at
  import validation** (`سایز` must belong to `خانواده سایز`; violations
  are a distinct error class). If a dependent dropdown is implemented
  later, it must remain exact-value based — no fuzzy or manual
  fallback.
- Date columns use date-typed cells; price columns use whole-number
  validation (≥ 1).

## Import mapping

Uniform rules for every physical column (per D-028):

- **Destination concepts:** `محصولات` rows → Product entity (D-021
  product fields + attributes + D-024 price fields + D-022/D-023
  statuses); `تنوع‌ها` rows → Product Variant + variant price fields;
  `راهنما` and `گزینه‌ها` are never imported.
- **Normalization:** trim surrounding whitespace; exact matching
  thereafter (D-019). Persian values are matched exactly; no case
  folding applies to Persian; Latin tokens (Product ID, SKU) are
  uppercased only where the format already requires it and the
  original value is retained.
- **Vocabulary resolution:** exact match against active terms
  (category within its primary; color globally; size within its
  family). Unmapped → retained + human review; never auto-added.
- **Provenance:** every imported value carries an `IMPORTED` record
  (D-026) with source reference = workbook + sheet + row + column +
  import event reference; original cell value retained where
  normalization occurred. The actor is the approved deterministic
  import tooling operating on behalf of the promoting human (recorded
  with the event); AI is never the actor.
- **Event:** one import run = one D-027 event (source system
  `excel-import`; event ID from the run or a deterministic content
  hash); identifier-level idempotency (D-017) applies per row and
  remains distinct from event-level idempotency.
- **Failure behavior:** row-level rejection with an actionable message;
  a failed run writes nothing; dry-run first; only a human promotes a
  dry-run to an actual import.

## Validation rules (deterministic)

| Case | Handling |
| --- | --- |
| duplicate Product ID (in sheet or against existing data) | reject row(s); never merge |
| duplicate Variant ID | reject; never merge |
| duplicate SKU | reject; never merge |
| duplicate Product ID + active Color + active Size combination | reject (D-014 rule 11) |
| invalid Product ID (format) | reject row |
| invalid Variant ID (non-canonical UUIDv4) | reject row |
| invalid SKU (format/unknown codes) | reject row; never auto-correct |
| unknown category / primary–leaf mismatch | reject row; value retained for human review |
| unknown color | reject row; value retained for human review |
| unknown size family | reject row |
| size not belonging to selected family | reject row |
| invalid price (non-numeric, ≤ 0, formatted string) | reject row |
| invalid sale price (≥ applicable base) | reject row; never clamped |
| invalid status value | reject row |
| missing required field | reject row (field-level error) |
| axis inconsistency (partially filled active axis) | reject affected rows |
| variant row without matching product row | reject row |
| publication requested but D-021 minimum unmet | surface at dry-run; blocked from `published` until human resolves |

No silent merging, no auto-correction of identifiers or
business-critical values, ever (D-028).

## Re-import (D-017 / D-027 — unchanged)

- Identical workbook re-imported → event-level skip (D-027) and
  identifier-level no-op (D-017); logged, nothing duplicated.
- Same identifiers + unchanged values → no-op.
- Same identifiers + changed values → **conflict: human review**; no
  silent update, no merge (D-017). Bulk field updates are not an Excel
  feature.
- Attempted change of an immutable identifier (Product ID, Variant ID,
  SKU) → rejected.
- Duplicate identifiers or combinations inside one workbook → rejected
  (see validation table).
- A corrected workbook is new content → new event; the human promotes
  it through a fresh dry-run.
